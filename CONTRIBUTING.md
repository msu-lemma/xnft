# Contributing Guidelines

Community contributions are welcome! We would appreciate feedback from the community in the form of bug reports, feature requets, and pull requests addressing open issues on the [Gitlab](https://www.gitlab.msu.edu/ece-lemma/public/xnft/xnft/-/work_items) / [GitHub](https://github.com/msu-lemma/xnft/issues).

> [!note]
> While we welcome community contributions, we are a small team working on this project part time, so we may take some time to respond to community feedback and contributions.

## Issues

If you find a bug or would like to request a feature, please first check if a similar issue already exists in [Work Items](https://www.gitlab.msu.edu/ece-lemma/public/xnft/xnft/-/work_items) or the [GitHub Issues](https://github.com/msu-lemma/xnft/issues).  If not, please [open an issue on the GitHub project](https://github.com/msu-lemma/xnft/issues).

> [!NOTE]
> Due to the development of this project initially starting on the MSU GitLab servers, issues (bugs and planned features) are currently tracked using the [GitLab Work Items](https://www.gitlab.msu.edu/ece-lemma/public/xnft/xnft/-/work_items). However, new issues and feature requests should be included and discussed on the GitHub to allow for community input.

## Pull Requests

Prior to opening a pull request, please ensure an issue for the bugfix or feature you are submitting a patch for.  This issue should be referenced in the pull request.  Additionally, please ensure the pull request template is used and all required fields have been verified (e.g., tests pass, code is formatted properly, documentation has been updated, etc.).  Finally, please note that all external contributions require a [Developer Certificate of Origin (DCO) sign-off](#dco-sign-off).

Community pull requests should be submitted to the [GitHub project](https://github.com/msu-lemma/xnft/issues) repository.  Pull requests will be reviewed in GitHub and either accepted, returned with feedback, or declined.  Once accepted, the pull request will be merged into the GitLab repository, which will be mirrored back upstream to GitHub.

## DCO Sign-off

All contributions to the repository must be signed using the Developer Certificate of Origin sign-off.

To add this sign-off to a commit automatically, use `git commit -s`.  This will automatically add the following trailer to your commit message:

```text
Signed-off-by: Your Name <name@example.com>
```

By applying this signature you certify that the commit adheres to the statements in the [Developer Certificate of Origin](DCO.txt).
